\section{Backend, Database, and Web-Client Source Code}
\label{sec:app_web_code}

This section reproduces the Node.js backend server, its rescoring utility, the Postgres migrations that define the fleet-monitoring schema, and the React source for both the administrator dashboard and the driver progressive web application. Each file is preceded by a compact summary block and followed by the stripped source listing.

\subsection*{Backend Server}

\subsection{Express Server}
\label{sec:code_backend_server}

\noindent\textbf{Purpose.} Node.js/Express HTTP server that hosts the ingest, alert-dispatch, and RPC endpoints consumed by the in-vehicle HMI, the LoRa gateway, the driver app, and the administrator dashboard.

\noindent\textbf{Inputs.} HTTPS POST payloads on the telemetry, gateway, trip, and alert endpoints; a Supabase JWT for authenticated dashboard requests; an HMAC-signed body for device-originated telemetry.

\noindent\textbf{Processes.} Validates identity and payload shape, resolves the active trip, computes GPS distance deltas through a Postgres RPC, forwards each row to the ML anomaly service, and writes to the alerts table so all client surfaces see the same state.

\noindent\textbf{Outputs.} JSON acknowledgement payloads, Supabase writes into the telemetry, trip-events, and alerts tables, and log lines for the deployment log.

\lstinputlisting[language=JavaScript,caption={Express server},label={lst:code_backend_server}]{code_listings/backend/server.js}

\subsection{Trip Rescoring Utility}
\label{sec:code_backend_rescore}

\noindent\textbf{Purpose.} One-shot script that rescores a previously stored trip against the current ML model version. Used to backfill anomaly flags after a model release.

\noindent\textbf{Inputs.} A trip identifier on the command line and a Supabase service-role key from the environment.

\noindent\textbf{Processes.} Reads all telemetry rows for the trip, re-invokes the ML service on each row in order, and overwrites the row's anomaly flag, score, and model source. Re-emits any alert that would fire under the current gate.

\noindent\textbf{Outputs.} A progress log, updated rows in the telemetry and alerts tables, and a non-zero exit code on validation failure.

\lstinputlisting[language=JavaScript,caption={Trip rescoring utility},label={lst:code_backend_rescore}]{code_listings/backend/rescore_trip.js}

\subsection*{Database Schema}

\subsection{Trip-Distance Odometer Accumulation}
\label{sec:code_sql_odometer_accum}

\noindent\textbf{Purpose.} Adds lifetime-mileage bookkeeping so each finished trip's distance is added exactly once to the truck's running odometer, working around the fact that the fleet's OBD-II adapter cannot read the vehicle's factory lifetime odometer directly.

\noindent\textbf{Inputs.} A finalised \texttt{trip\_sessions} row with a valid \texttt{distance\_km}.

\noindent\textbf{Processes.} Extends \texttt{trip\_sessions} with an accumulation flag, defines an update function that adds the trip distance to \texttt{trucks.current\_odometer\_km}, and wires a trigger that fires on trip end.

\noindent\textbf{Outputs.} A schema in which every ended trip advances the truck odometer once and only once.

\lstinputlisting[language=SQL,caption={Trip-distance odometer accumulation},label={lst:code_sql_odometer_accum}]{code_listings/supabase/20260622091500_trip_distance_odometer_accumulation.sql}
